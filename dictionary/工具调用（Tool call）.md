[模型](./模型（Model）.md)输出中指明[工具](./工具（Tool）.md)名称及其参数的结构化文本。它本身不会执行任何操作，必须由 [Harness](./Harness（驾驭框架）.md) 读取并执行。它由模型在单次[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)中生成。

一次工具调用的生命周期：

| 步骤 | 执行方  | 发生的事情                                                               |
| ---- | ------- | ------------------------------------------------------------------------ |
| 1    | 模型    | 从 [System prompt](./System%20prompt（系统提示词）.md) 的描述中了解有哪些工具可用      |
| 2    | 模型    | 输出一次调用——工具名称加参数（通常是 JSON）——然后停止生成                |
| 3    | Harness | 解析该调用，并根据[权限模式](./权限模式（Permission%20mode）.md)进行检查             |
| 4    | Harness | 若允许，则执行该调用                                                     |
| 5    | Harness | 在下一次请求中将执行结果作为[工具返回结果](./工具返回结果（Tool%20result）.md)发回给模型 |

[Agent](./Agent（智能体）.md) 工作的一个[轮次](./轮次（Turn）.md)，通常是由多次这样的往返调用串联而成的。

由于工具调用和其他输出一样，都是通过[下一个 Token 预测](./下一个%20Token%20预测（Next-token%20prediction）.md)生成的，它也可能像任何模型输出那样出错：一个不存在的路径、一个命令根本没有的标志位、或者看起来合理但实际错误的参数。Harness 执行的是模型实际写出的内容，而不是它“意图”表达的内容——一个拼错的路径不会优雅地报错提醒，而是会直接去编辑错误的文件。

_用法示例：_

“它说它跑了测试，但文件的时间戳根本没变。”

“去看看会话记录——它真的发起了工具调用，还是只是在文字里描述自己跑了测试？模型负责生成调用文本，但如果 Harness 没有真正执行它，那就什么都没发生。”
