不向后保留任何信息。[模型](./模型（Model）.md)在多次[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)之间是无状态的——每次请求都会重新发送完整的[上下文窗口](./上下文窗口（Context%20window）.md)，因为模型除此之外看不到任何其他信息。一个 [Agent](./Agent（智能体）.md) 在不同[会话](./会话（Session）.md)之间默认也是无状态的：新会话总是空白开启，不保留先前会话的任何痕迹。与[有状态](./有状态（Stateful）.md)相对。

模型本身是永久无状态的：它的[参数](./参数（Parameters）.md)在[训练](./训练（Training）.md)完成后就已冻结，你在[推理](./推理（Inference）.md)阶段所做的任何操作都不会改变这些参数。模型不会从你的纠正中学习，不记得昨天被告知过同样的事情，也不会逐渐“了解”你——无论对话给人的感觉有多像那么回事。单次会话中的连续感是由 [Harness](./Harness（驾驭框架）.md) 制造出来的：它保存着对话记录，并在每次请求时重新发送给模型。模型并不是在“回忆”对话，而是在“重读”对话。

由此带来的实际影响是：如果你想让某些信息在跨会话时被记住，就必须把它写到 Agent 能够重新读取的地方。[AGENTS.md](./AGENTS.md.md) 文件、[记忆系统](./记忆系统（Memory%20system）.md)和[交接产物](./交接产物（Handoff%20artifact）.md)正是为此而存在——它们会被加载到未来会话的[上下文](./上下文（Context）.md)中，以此替代模型本身并不具备的记忆能力。当 Agent 反复犯你之前已经纠正过的错误时，问题不在于它“为什么学不会”——它根本学不会——而在于这条纠正应该写在哪里，才能让之后的每一次会话都读到它。

_用法示例：_

“为什么我每次[清空会话](./清空会话（Clearing）.md)之后，它就把规范忘了？”

“模型是无状态的——新会话都是从零开始。如果想让它延续下来，就写进 AGENTS.md 或 Harness 在会话开始时会加载的记忆文件里。”
