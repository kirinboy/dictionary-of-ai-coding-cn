在[会话](./会话（Session）.md)初期，[Agent](./Agent（智能体）.md) 处于“聪明区”——敏锐、专注、召回准确。随着会话变长，它会逐渐滑入“愚钝区”：变得敷衍、健忘、频频出错——忠实度[幻觉](./幻觉（Hallucination）.md)也会增多。还是同一个[模型](./模型（Model）.md)、同一个 [Harness](./Harness（驾驭框架）.md)——仅仅是[上下文](./上下文（Context）.md)变多了。这就是[注意力退化](./注意力退化（Attention%20degradation）.md)带来的直观感受。在前沿模型上，愚钝区通常大约从 125K-150K [Token](./Token（词元）.md) 开始——尽管具体阈值仍有争议。当会话膨胀时，应及时[清空会话](./清空会话（Clearing）.md)或进行[上下文压缩](./上下文压缩（Compaction）.md)，不要硬撑着继续。

这种滑坡是渐进的，因此很容易被忽略。既没有报错信息，也没有肉眼可见的边界；Agent 只是起初表现略差一点，随后变得明显更差。常见迹象包括：忘记你二十轮之前给过的指令、重复犯已经纠正过的错误，或者自信满满地断言某件与上下文相矛盾的事。正因为下滑过程十分平滑，人们通常的反应是硬着头皮继续并重新解释一遍——这反而会增加更多上下文，让问题更严重。

聪明区与愚钝区并不等同于[上下文窗口](./上下文窗口（Context%20window）.md)上限。哪怕窗口还有大半空闲，一个会话也可能早已深陷愚钝区：窗口上限只是 Harness 拒绝继续运行的节点，而输出质量早在此之前就已大幅滑坡。规划任务时要围绕聪明区，而不是围绕窗口上限——一项任务的实际可用预算，是 Agent 能保持良好表现的 Token 范围，而不是它技术上最多能装下的 Token 数量。

聪明区是一种预算，无关的工作会消耗它。在同一个会话里完成的每项任务都会占用 Token，因此在同一个会话里开启第二项任务，意味着它从一开始就离愚钝区更近。每个会话只做一件事，才能让每项任务都享受到会话中最敏锐的阶段。当单个任务的体量超过一个聪明区时，就把它拆开：在自然边界处进行[交接](./交接（Handoff）.md)或压缩，让一个全新的会话来接手下一部分。

_用法示例：_

“前三个组件它写得漂亮极了，到了第四个却直接写砸了。”

“你已经走出聪明区了——还是同一个模型，只是现在深陷愚钝区了。压缩一下并重新加载计划，下一个组件就能稳稳落地。”
