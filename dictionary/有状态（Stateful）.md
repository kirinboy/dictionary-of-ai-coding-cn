向后保留信息。一个[会话](./会话（Session）.md)在多个[轮次](./轮次（Turn）.md)之间是有状态的——随着会话推进，[上下文](./上下文（Context）.md)会不断累积，这也是为什么长会话会逐渐滑向[愚钝区](./聪明区（Smart%20zone）.md)。通过引入[记忆系统](./记忆系统（Memory%20system）.md)，将信息持久化到[环境](./环境（Environment）.md)中并在后续会话开始时重新加载，[Agent](./Agent（智能体）.md) 也可以在多个**会话**之间变得有状态。[模型](./模型（Model）.md)本身永远不是有状态的；任何看似连续的状态，都是 [Harness](./Harness（驾驭框架）.md) 重新喂给模型的上下文。与[无状态](./无状态（Stateless）.md)相对。

各层中状态的存放位置如下：

| 层级    | 是否有状态？ | 实现方式                                                                                                       |
| ------- | ------------ | -------------------------------------------------------------------------------------------------------------- |
| 模型    | 从不         | [参数](./参数（Parameters）.md)是冻结的；它只能看到每次请求中传入的内容                                                |
| 会话    | 跨轮次       | Harness 将每条消息和[工具返回结果](./工具返回结果（Tool%20result）.md)追加到上下文中                                           |
| Harness | 跨会话       | 记忆文件、[AGENTS.md](./AGENTS.md.md)、[交接产物](./交接产物（Handoff%20artifact）.md)——写入保存，后续重新加载             |
| 环境    | 始终         | 无论是否有会话在运行，文件都会持久存在                                                                         |

每一层的有状态性，都是通过重新读取下一层存储的内容构建出来的：会话之所以显得连贯，是因为 Harness 把消息历史重新发送给了无状态的模型；Agent 之所以能跨会话记住事情，是因为 Harness 从环境中重新加载了文件。没有任何状态是真正存储在模型自身之内的。

状态并不总是好事。所有向后保留的内容都会影响接下来的输出，因此会话早期做出的错误假设也会被一路带下去。[清空会话](./清空会话（Clearing）.md)正是刻意丢弃当前会话状态、仅从已落盘的书面记录重新开始的操作。

_用法示例：_

“它记住了我昨天的偏好——这说明模型把它们学进去了吗？”

“不是的，Agent 表现得有状态，是因为 Harness 把偏好写进了记忆文件并在新会话开始时重新加载了。模型本身对昨天发生的事一无所知。”
