description: Agent 当前可直接从上下文中读取到的事实。与参数知识相对应。
---

[Agent](./Agent（智能体）.md) 此刻能直接从[上下文](./上下文（Context）.md)中读取到的事实——用户布置的任务、Agent 读入的文件、[工具返回结果](./工具返回结果（Tool%20result）.md)，以及[会话](./会话（Session）.md)开始时加载的 [AGENTS.md](./AGENTS.md.md) 内容。与[参数知识](./参数知识（Parametric%20knowledge）.md)相对应：参数知识是从参数中_回忆_出来的；上下文知识是从[上下文窗口](./上下文窗口（Context%20window）.md)中_读取_出来的。当 Agent 依托上下文知识工作时，[幻觉](./幻觉（Hallucination）.md)会少得多——答案就摆在眼前，无需从模糊的记忆里打捞。

在这两种知识中，只有上下文知识在你的掌控之中。参数是冻结的，因此要想给[模型](./模型（Model）.md)补充它缺乏的知识——比如内部 SDK、[知识截止日期](./知识截止日期（Knowledge%20cutoff）.md)之后发布的库、昨天刚敲定的决策——唯一的办法就是把它放进上下文。大量实际的 [AI](./AI（人工智能）.md) 编程工作归根结底就是这件事：在模型需要的时候，把正确的事实摆到它面前。

当上下文知识与参数知识冲突时，通常由上下文知识胜出。贴入最新的 API 文档，模型就会照着新文档写，而不是顺着对旧 API 的陈旧记忆——不过旧版本有时仍会渗透进来，尤其是在长会话的后期。如果尽管已经加载了文档，Agent 还是反复退回到过时写法，那就是参数知识压过了上下文知识；此时重申纠正意见，或把它移到离当前工作更近的位置会有所帮助。

与参数知识不同，使用上下文知识是有成本的。加载进窗口的每一点内容都会消耗 [Token](./Token（词元）.md)，并争夺模型的[注意力预算](./注意力预算（Attention%20budget）.md)，因此塞得越多并不自动更好——目标是让窗口里放着相关的事实，而不是所有的事实。

_使用时机：_ 仅在需要与参数知识对比时才使用这个词；其他情况直接说**上下文**即可。

_避免使用：_ “工作记忆（working memory）”——上下文知识是指_此刻_窗口里有什么；[记忆系统](./记忆系统（Memory%20system）.md)则是负责把跨会话的内容送进窗口的机制。两者尺度不同，不要混为一谈。

_用法示例：_

“为什么我贴了文档它就能写对 API，不贴的时候它就开始瞎编？”

“贴了文档就是上下文知识——照着书本念。不贴就只能靠参数知识，那些冷门接口自然就模糊了。”
