[Agent](./Agent（智能体）.md) 当前可访问的相关信息。这是一个抽象概念——它指的不是模型看到的原始输入（那是[上下文窗口](./上下文窗口（Context%20window）.md)），也不是持续累积的对话历史（那是[会话](./会话（Session）.md)），而是 _Agent 所掌握的与当前任务直接相关的内容_。“把某样东西加载进上下文”意味着将其纳入这个信息集合；“上下文工程（context engineering）”则是精心筛选并组织这组信息的实践。

这三个概念的界限非常清晰：

| 术语       | 所指代的内容                                                         |
| ---------- | -------------------------------------------------------------------- |
| 上下文     | Agent 当前掌握的、与任务相关的信息                                   |
| 上下文窗口 | 模型在每次请求中实际看到的 [Token](./Token（词元）.md) 序列                  |
| 会话       | [Harness](./Harness（驾驭框架）.md) 存储的持续对话记录                           |

区分这三者很重要，因为上下文衡量的是质量，而不是数量。一个上下文窗口可能已经快满了，但其中的上下文质量依然很差——塞满了数千 Token 过时的工具输出，却没有一条和眼下的任务相关。反之，上下文窗口也可能几乎是空的，但上下文却极佳：比如里面恰好只有决定当前任务成败的那一个类型定义。

日常使用中的大多数失败都可以追溯到上下文问题。当 Agent 捏造了一个 API、推翻了先前的决定，或者开始猜测某个数据结构时，首先应该检查它当时上下文里有什么——通常是因为关键事实从未被加载进去，或者已经被淹没在[注意力退化](./注意力退化（Attention%20degradation）.md)之中。解决办法就是做好信息筛选：加载任务真正需要的内容，把无关的挡在外面。

_用法示例：_

“它一直在编造类型里根本不存在的字段。”

“那个类型文件不在上下文里——它只读了调用方代码就在那儿瞎猜。先把类型定义读进去。”
