与 [Agent](./Agent（智能体）.md) 进行的一段有边界的交互过程。它从空白开始，不断累积消息、[工具返回结果](./工具返回结果（Tool%20result）.md)以及读取过的文件，并在[清空会话](./清空会话（Clearing）.md)、关闭或通过[上下文压缩](./上下文压缩（Compaction）.md)转为新会话时结束。会话正是_填满_[上下文窗口](./上下文窗口（Context%20window）.md)的内容：如果把上下文窗口比作一个盒子，会话就是慢慢装满它的东西。超出单个上下文窗口承载能力的工作，必须拆分成多个会话来完成。

会话的消息历史就是 Agent 的工作记忆。[模型](./模型（Model）.md)是[无状态](./无状态（Stateless）.md)的，所以它看起来记住的一切——你提的要求、测试输出的结果、三个轮次前做出的决定——全都保存在消息历史里，并在每次[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)时重新发送。凡是不在会话中的东西，对 Agent 而言都不存在。

这份记忆会随着会话的结束而消失。新会话总是从零开始：昨天会话结束时对你的代码库了如指掌的 Agent，今天早上会变得一无所知。真正留存下来的是[文件系统](./文件系统（Filesystem）.md)——上一个会话中写入的文件可以被下一个会话读取，这也是[交接](./交接（Handoff）.md)、[记忆系统](./记忆系统（Memory%20system）.md)和 [AGENTS.md](./AGENTS.md.md) 得以发挥作用的基础。

会话在哪里结束由你决定。会话里的每一条信息都会影响后续的每一个[轮次](./轮次（Turn）.md)，因此在同一个会话里做不相关的任务，会留下干扰后续回答的残留信息。一个会话只做一件事能保持上下文的高度相关；完成一项任务正是清空会话的自然节点。

_用法示例：_

“一个会话能跑多久才开始掉链子？”

“看具体任务——目标明确的重构能比开放式调研撑得久得多。一旦会话开始臃肿，就做交接或压缩，别硬撑。”
