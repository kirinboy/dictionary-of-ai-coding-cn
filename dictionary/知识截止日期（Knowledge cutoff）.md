---
description: 模型参数知识所覆盖的截止日期。截止日期之后出现的库和 API 若不加载文档，就容易成为编造陷阱。
---

[模型](./模型（Model）.md)拥有[参数知识](./参数知识（Parametric%20knowledge）.md)的截止日期。在此日期之后出现的库、API 和事件都是编造陷阱，除非把它们的文档作为[上下文知识](./上下文知识（Contextual%20knowledge）.md)加载进来。每个模型发布时都有各自的截止日期。

截止日期的存在源于模型的构建方式：[训练](./训练（Training）.md)将一份文本快照烘焙进模型的[参数](./参数（Parameters）.md)中，此后参数便被冻结。模型并不知道自己的知识有边界——被问到截止日期之后的内容时，它不会拒绝回答，而是从自己已知的最相近内容出发去外推。这正是这个陷阱难以察觉的原因：按旧版本库写出的代码看起来合情合理，往往还能编译通过，却偏偏在发生变更的部分出错。

解决办法始终一致：把最新信息放进[上下文](./上下文（Context）.md)。加载更新日志、指向当前安装版本的类型定义，或让 Agent 从网页读取文档。上下文里有什么，都胜过参数里什么都没有。

_用法示例：_

“它一直在写 v3 版本的 SDK 语法——可我们已经升到 v5 了。”

“v5 是在知识截止日期之后发布的。把 v5 的更新日志作为上下文知识加载进去，否则它会一直按参数里的旧版本去编造。”
