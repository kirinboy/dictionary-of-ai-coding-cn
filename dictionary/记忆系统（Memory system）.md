一种试图让 [Agent](./Agent（智能体）.md) 跨[会话](./会话（Session）.md)保持[有状态](./有状态（Stateful）.md)的系统。它在会话期间将信息持久化到[环境](./环境（Environment）.md)中，并在后续会话开始时将其重新加载到[上下文窗口](./上下文窗口（Context%20window）.md)中，使 Agent 在用户[清空会话](./清空会话（Clearing）.md)后仍能保持连续性。

记忆系统包含写入和读取两条路径。写入路径：在会话期间，Agent 将学到的内容（例如你表达过的偏好、关于项目的事实）作为文件记录在环境中。读取路径：在会话开始时，[Harness](./Harness（驾驭框架）.md) 将这些文件或其索引重新加载回上下文窗口。许多 Harness 自带记忆系统——例如 Claude Code 的 `/memory`——但你也可以自己搭建一个：建一个笔记目录，再在 [AGENTS.md](./AGENTS.md.md) 中加一条指令让 Agent 去查阅它。

它与所有常驻加载的内容一样存在权衡。记忆会不断积累，因此大多数系统只加载单行索引，把正文留在[上下文指针](./上下文指针（Context%20pointer）.md)后面，而不是把所有内容都内联进去。此外，记忆属于[二手信源](./二手信源（Secondary%20source）.md)，因此会发生漂移：三月记录的事实，到了六月项目已经发生变化后，仍会被以同样的置信度加载。记忆系统需要定期修剪，就像 AGENTS.md 一样。

_用法示例：_

“我总得反复提醒它我用的是 Postgres，不是 MySQL。”

“接一个记忆系统吧——第一[轮次](./轮次（Turn）.md)就把学到的东西写进[文件系统](./文件系统（Filesystem）.md)，会话开始时再重新加载。[模型](./模型（Model）.md)本身是[无状态](./无状态（Stateless）.md)的，记忆层只是在模拟连续性。”
