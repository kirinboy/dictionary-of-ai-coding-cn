供 [Agent](./Agent（智能体）.md) 在其中运行的隔离[环境](./环境（Environment）.md)——容器、虚拟机、临时[文件系统](./文件系统（Filesystem）.md)或权限受限的 Shell。它用于限制 Agent 操作的爆炸半径：即使 Agent 运行了破坏性命令或拉取了恶意内容，损害也会被控制在隔离边界内。它是让[无人值守（AFK）](./无人值守（AFK）.md)变得切实可行的安全基座。

沙箱和[权限模式](./权限模式（Permission%20mode）.md)是从相反的两端解决同一个问题。权限模式是在操作运行前询问；沙箱则是限制操作一旦运行后能触及的范围。权限模式需要你保持[人在回路（HITL）](./人在回路（Human-in-the-loop）.md)——每次提示都是一次打断——一个不停弹窗询问的会话几乎谈不上自主。沙箱是用基础设施来换取注意力：隔离越强，需要询问的问题就越少。

隔离有不同等级：

| 等级       | 它是什么                                           | 它能兜住什么                           |
| ---------- | -------------------------------------------------- | -------------------------------------- |
| 受限 Shell | 围绕每条命令的操作系统级限制                       | 项目目录之外的写入、网络访问           |
| 容器       | 全新文件系统，不挂载凭证，用完即毁                 | Agent 对自身所在机器所做的任何操作     |
| 虚拟机/云端 | 一台完全独立的机器，通常由 Harness 提供            | 一切操作，包括内核级逃逸               |

没有任何沙箱能兜住的，是那些被合法允许离开边界的操作。一个拥有你 git 凭证的 Agent 可以推送代码；一个拥有网络访问权限的 Agent 可以调用生产环境 API。在决定把沙箱建得多厚之前，先决定好允许哪些东西跨越边界。

_用法示例：_

“我想让它在 [bypass-permissions](./Agent%20模式（Agent%20mode）.md) 模式下跑通宵，但我还没准备好担这个风险。”

“把它放进沙箱里——全新容器、不挂载任何凭证、禁止外网出站。最坏的情况也不过是它把自己的文件系统炸掉，你直接把容器删了就行。”
