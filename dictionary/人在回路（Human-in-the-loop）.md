一种工作模式：在[会话](./会话（Session）.md)期间，一名或多名人类与 [Agent](./Agent（智能体）.md) 实时配合——随时审查、纠正方向或共同协作。人类全程在场并深度参与，而不仅仅是在单个操作前把关。

与[无人值守（AFK）](./无人值守（AFK）.md)模式相对——在 AFK 模式下，Agent 自主运行，事后再由你评判结果。人在回路（HITL）意味着在代价还很低的时候就发现问题：你看到 Agent 找错了文件、误解了需求，或者走进了死胡同，只需一句话就能把它拉回正轨——而不必在二十分钟后才发现它基于那个错误一路自信地写了一大堆代码。Agent 并不总能意识到自己已经偏离方向；无人看管时，它们往往会继续硬着头皮往下推进，而不是停下来发问。

具体采用哪种模式取决于任务性质。需求明确、风险较低、易于验证的任务适合 AFK；而需求模糊、不可逆，或者事后很难审查最终结果的任务——比如数据库 Schema 迁移、棘手的设计决策、任何涉及生产环境的操作——则适合让人保持在回路中。本质上这是一个权衡判断：走错一步的代价有多高？以及你会在多晚的时候才发现它？

有些工作天生就必须在回路中完成，因为你的即时反馈本身就是输入。[追问式访谈（Grilling）](./追问式访谈（Grilling）.md)需要你在场回答问题才能推进；[原型构建](./原型构建（Prototyping）.md)需要你在场对着产物给出反应才能迭代。

保持在回路中会消耗你的注意力，而注意力正是稀缺资源。用好 Agent 的进阶之道，在于借助计划、[自动化检查](./自动化检查（Automated%20check）.md)以及事后的[人工审查](./人工审查（Human%20review）.md)，把更多工作安全地移出回路，而不是全程盯守。[软件工厂](./软件工厂（Software%20factory）.md)则更进一步，直接通过触发器启动会话，连发起任务这一步都不再需要人工介入。

_用法示例：_

“这个任务今晚开无人值守（AFK）跑完吗？”

“不行，这是 Schema 迁移——保持人在回路（HITL）。我要看着每一步，万一它选错了用来回填数据的列，我得及时纠正。”
