[Harness](./Harness（驾驭框架）.md) 在执行未经预先批准的[工具调用](./工具调用（Tool%20call）.md)之前向用户展示的确认请求。[模型](./模型（Model）.md)生成一次工具调用后，Harness 不会立即运行它，而是暂停下来向你询问。批准则执行；拒绝则由 Harness 将拒绝信息作为[工具返回结果](./工具返回结果（Tool%20result）.md)传回给模型。这就是 Harness 在面对高风险或敏感操作时实现[人在回路（HITL）](./人在回路（Human-in-the-loop）.md)的机制。

一次权限请求的生命周期：

| 步骤 | 执行方  | 发生的事情                                                           |
| ---- | ------- | -------------------------------------------------------------------- |
| 1    | 模型    | 生成一次工具调用                                                     |
| 2    | Harness | 根据[权限模式](./权限模式（Permission%20mode）.md)和已保存的批准记录进行检查     |
| 3    | Harness | 若已预先批准：立即执行。否则：暂停并向用户展示该请求                 |
| 4    | 用户    | 选择单次批准、本[会话](./会话（Session）.md)内始终批准，或拒绝               |
| 5    | Harness | 执行该调用，或将拒绝信息作为工具返回结果发回                         |

拒绝一次请求能够引导 Agent 的行为。模型会像读取其他工具返回结果一样读取这条拒绝信息并作出反应——尝试另一种方案，或者询问你的偏好。大多数 Harness 允许你在拒绝时附带一条消息，这让权限请求变成了一个方向纠正点：“别这么干，改用迁移脚本”，恰好能在模型决定下一步做什么时送达。

其代价是每一次请求都需要你同步等待并响应。[Agent](./Agent（智能体）.md) 会一直阻塞直到你回答，这在你盯着屏幕时不成问题，但当你离开时就会成为障碍——一个频繁触发权限请求的 Agent 无法进入[无人值守（AFK）](./无人值守（AFK）.md)状态。权限模式就是调节这一平衡的旋钮：哪些调用可以自由运行，哪些需要先询问；理想情况下配合[沙箱](./沙箱（Sandbox）.md)使用，可以安全地扩大自由执行的范围。

_用法示例：_

“它卡在权限请求上整整十分钟了——我刚才在开会。”

“这就是人在回路的代价。把安全的[工具](./工具（Tool）.md)设为预先批准，让请求只在真正有风险的调用上触发。”
