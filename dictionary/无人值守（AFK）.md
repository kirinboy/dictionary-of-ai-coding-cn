Away from keyboard（离开键盘）。一种工作模式：用户启动[会话](./会话（Session）.md)后离开，让 [Agent](./Agent（智能体）.md) 无人值守地自主运行。这是 [AI](./AI（人工智能）.md) 编程的吞吐量倍增器——在你睡觉、吃饭或处理其他事情时，可以同时并行运行多个 AFK 会话。为了确保安全，通常需要配合宽松的[权限模式](./权限模式（Permission%20mode）.md)和[沙箱](./沙箱（Sandbox）.md)机制。

当你不在场时，Agent 处理歧义的方式会截然不同。你在盯着的时候，遇到拿不准的决策它会提问，由你来拍板；一旦你走开了，Agent 就会自行选一个默认方案继续往下走，而后续的每一个决策都会建立在这个猜测之上。这种模式下最典型的翻车现场，就是你回来后看到几个小时完成的一堆看似严谨、自信满满的工作，结果全都是建立在最初十分钟里做出的一个错误判断上。这些代码并不敷衍——它逻辑自洽，只是在错误的方向上自洽。

既然在运行过程中无法给出输入，那就把输入前移和后置。运行前：提前消除歧义——做一次[追问式访谈（Grilling）](./追问式访谈（Grilling）.md)，或者写一份清晰的 [Spec](./Spec（规格说明书）.md)——尽量减少留给 Agent 自行脑补的空白。运行中：用[自动化检查](./自动化检查（Automated%20check）.md)和[自动化审查](./自动化审查（Automated%20review）.md)来替代你缺席的注意力，对机械性错误做到快速失败。运行后：任务产出必须是一个可供审查的结果——比如一个 PR，而不是直接合并进主干的改动。AFK 并没有取消[人工审查](./人工审查（Human%20review）.md)，只是把它全部推迟到了最后，因此最后呈现在你面前的东西必须值得审查。这也是为什么 [Agent体验（AX）](./Agent体验（AX）.md) 在 AFK 运行中尤为重要——在无人看管时，环境就是 Agent 唯一能依靠的支撑。

_避免使用：_ “后台 Agent（background agent）”——这种说法把重心放在了机器上（“在后台运行”），而不是人类的工作模式（“用户离开了”）。AFK 准确点出了关键事实：用户此刻没有在盯着。

_用法示例：_

“我把这批重构设为无人值守（AFK）跑了——三个沙箱隔离的 Agent 同时在改，明早起来再审查 PR。”

“开了[跳过权限检查](./Agent%20模式（Agent%20mode）.md)吗？”

“开了，只读[文件系统](./文件系统（Filesystem）.md)，而且断了网。”
