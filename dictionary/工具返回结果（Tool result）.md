[Harness](./Harness（驾驭框架）.md) 执行[工具调用](./工具调用（Tool%20call）.md)后发回的内容——文件内容、命令输出或错误信息。它是 [Agent](./Agent（智能体）.md) 观察[环境](./环境（Environment）.md)的唯一窗口。它会在_下一次_[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)中传回给[模型](./模型（Model）.md)，由模型决定接下来该如何处理。工具调用与工具返回结果是同一次交互的两端，共同发生在同一个[轮次](./轮次（Turn）.md)内。

工具返回结果的生命周期：

| 步骤 | 执行方  | 发生的事情                                                       |
| ---- | ------- | ---------------------------------------------------------------- |
| 1    | Harness | 执行工具调用——运行命令、读取文件                                 |
| 2    | Harness | 捕获结果：输出内容、文件内容或错误信息                           |
| 3    | Harness | 将其作为一条消息追加到[上下文](./上下文（Context）.md)中                   |
| 4    | Harness | 在下一次模型提供商请求中将完整上下文发送给提供商                 |
| 5    | 模型    | 读取该结果并做决定：发起另一次工具调用，或给出最终答复           |

返回结果会在剩余的[会话](./会话（Session）.md)期间一直留在上下文中。在编程会话的上下文里，工具返回结果通常占据了绝大部分篇幅：每一次读取文件、每一次运行测试、每一次搜索，其结果都会完整地落入上下文，并在失去实际用处很久之后依然持续占用 [Token](./Token（词元）.md)。只需几个体积较大的返回结果——比如冗长的测试日志、被整份读取的生成文件——就能比对话本身更快地把会话推向[上下文窗口](./上下文窗口（Context%20window）.md)的极限。

正因为返回结果是模型看到的全部信息，模型无法绕过它去核对背后的真实环境。如果输出被截断、命令静默失败，或者 Harness 返回了错误信息而非文件内容，模型就只能基于它收到的内容进行推理。当你觉得 Agent 对系统的认知明显不对劲时，去检查工具返回结果就对了：会话记录的某个地方，一定有一条返回结果与你所知的事实不符。

_用法示例：_

“它一直在按空文件的逻辑来推理这个文件。”

“当时的工具返回结果是一条权限拒绝提示，而不是文件内容。模型只看到了那行报错字符串——它没有其他途径能看到那个文件。”
