即[参数](./参数（Parameters）.md)本身。它是[无状态](./无状态（Stateless）.md)的——只做[下一个 Token 预测](./下一个%20Token%20预测（Next-token%20prediction）.md)，除此之外什么也做不了。“Claude Opus 4.x”和“GPT-5.x”都是模型。仅靠自身，模型无法完成任何具备 Agent 能力的事情；它必须由 [Harness](./Harness（驾驭框架）.md) 来驱动。

模型本身无法读取文件、运行命令、浏览网页或记住昨天的事——它在每次[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)中接收输入 [Token](./Token（词元）.md)，并预测输出 Token。所有让你感觉像是一个 [Agent](./Agent（智能体）.md) 在自主工作的过程——选择[工具](./工具（Tool）.md)、读取结果、循环往复直到任务完成——实际上都是 Harness 在连续编排大量的预测请求。

[模型提供商](./模型提供商（Model%20provider）.md)通常会分档位提供模型：大型模型最聪明，但速度慢、价格高；小型模型更快、更便宜，但能力较弱。选择哪个档位是一个实打实的权衡决策——规划和疑难调试用重型模型，机械性修改用轻量模型——而 Harness 也允许你在[会话](./会话（Session）.md)中途切换模型。

严格区分“模型”这个词还能让问题定位更精准。“这个模型在这件事上表现很差”是一个非常具体的论断——同一个模型换一个 Harness，或者换一份[上下文](./上下文（Context）.md)，表现往往会截然不同。在怪罪模型之前，先检查一下它收到了什么输入：大多数令人失望的输出，根源都在上下文或 Harness，而非参数。

_用法示例：_

“规划这一步我们要不要把模型从 Sonnet 换成 Opus？”

“可以试试——但这个任务里主要是 Harness 在起作用。如果 [System prompt](./System%20prompt（系统提示词）.md) 和工具配错了，换模型也无济于事。”
