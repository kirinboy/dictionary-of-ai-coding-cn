推理强度（Effort）是一个旋钮，用来调节[模型](./模型（Model）.md)在给出答案前要进行多少推理。它按[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)进行设置，控制着模型在开始输出你所看到的正式回答之前，先行开展的思考长度。这些思考过程与其他内容一样，都是在[推理](./推理（Inference）.md)时生成的；[Harness](./Harness（驾驭框架）.md) 往往会将其隐藏，但这确实是模型正在做的真实计算。

更高的推理强度意味着更高的费用和更慢的速度。推理过程同样以 [Token](./Token（词元）.md) 的形式输出，即便你从界面上看不到，也会按[输出 Token](./输出%20Token（Output%20tokens）.md) 计费；而且 Token 是一个接一个生成的——因此调高推理强度既会拉长等待回答的时间，也会增加账单金额。这本质上是在用速度和成本，换取更充分的思考。

大多数 Harness 会把推理强度暴露为一个简单的档位阶梯：

| 档位   | 适用场景                                               |
| ------ | ------------------------------------------------------ |
| Low    | 机械性编辑、简单查询、路径唯一且明确的修改任务。       |
| Medium | 日常编码——通常的默认档位。                             |
| High   | 棘手的 Bug、架构设计决策、多步骤规划。                 |
| Max    | 最困难的问题，一旦答错就需要付出高昂的返工代价。       |

档位选错在两个方向上都会出问题。在难题上把推理强度设得太低，你会得到一个自信却肤浅的答案，因为它跳过了问题所需的推理——表面读起来头头是道，实则是错的，后续会让你付出代价。而在单行重命名这种小事上设成 Max，你就会白白看着它思考半天，最后产出跟最低档位毫无差别的结果。

请按具体任务来匹配推理强度，而不是按整个[会话](./会话（Session）.md)一刀切。在真正需要深度推理的环节调高它，在周围的常规杂活上调低它。

_用法示例：_

“它老是把这个并发修复改砸——我已经解释三遍了。”

“把推理强度调高吧。这是个重推理的 Bug，默认档位下它还没想清楚就急着动手写方案了。”
