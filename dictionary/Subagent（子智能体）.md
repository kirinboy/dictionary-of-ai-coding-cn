由另一个 [Agent](./Agent（智能体）.md) 通过[工具调用](./工具调用（Tool%20call）.md)生成的 Agent。它在自己的[会话](./会话（Session）.md)和独立的[上下文窗口](./上下文窗口（Context%20window）.md)中运行，并向父 Agent 返回单一的[工具返回结果](./工具返回结果（Tool%20result）.md)。它不同于[交接](./交接（Handoff）.md)——父 Agent 明确期待一个返回结果，而交接没有返回路径。**不能再生成更深层的 Subagent**——调用树只有一层深度。Subagent 的存在是为了隔离[上下文](./上下文（Context）.md)，而不是为了层层嵌套。

这样做的目的是把嘈杂的中间过程隔离在父 Agent 的上下文之外。一次大范围搜索或一长串文件读取会产生好几页的工具返回结果，其中大部分内容只在找到答案的那一刻有用。如果在父 Agent 内部直接执行，所有这些结果都会一直留在父上下文里直到会话结束；如果在 Subagent 中执行，这些噪音就会填进一个用完即弃的窗口里——只有最终报告会进入父 Agent 的上下文。这份报告属于[二手信源](./二手信源（Secondary%20source）.md)：父 Agent 拿到的是 Subagent 对所见内容的转述，而不是原始结果，因此报告里遗漏的任何信息对父 Agent 来说都是不可见的。

Subagent 还可以并发运行——父 Agent 可以同时派出多个 Subagent，分别处理彼此独立的工作片段。

_用法示例：_

“grep 的结果把我的上下文撑爆了。”

“派一个 Subagent 去搜吧——它会把噪音消耗在自己的上下文窗口里，最后只把你真正需要的那两个文件路径报回来。”
