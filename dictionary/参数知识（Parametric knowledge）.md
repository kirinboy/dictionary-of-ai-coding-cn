[模型](./模型（Model）.md)在[训练](./训练（Training）.md)中“习得”并存储在[参数](./参数（Parameters）.md)里的内容。它在训练完成时即被冻结——模型既无法查看自己的参数，也无法更新它们。在压缩过程中会有细节流失：数十亿条事实被塞进数量有限的参数中，冷门细节就会变得模糊。这既是模型在常见话题上对答如流的原因，也是在冷门话题上凭空编造的根源。与[上下文知识](./上下文知识（Contextual%20knowledge）.md)相对应。

参数知识并非以“事实条目”的形式存储。训练过程从未给模型提供一个可供检索的数据库；它只是不断调整参数，直到模型能很好地预测文本，而一个能精准预测某话题文本的模型，表现起来就像“懂”这个话题一样。知识的可靠程度取决于该内容在训练数据中出现的频率：有数百万条样本的话题，模型能准确复现；只有寥寥几条样本的话题，模型只能参照相似话题去猜测。对模型而言，复现和猜测是同一个过程，因此它自己也分不清在做什么。编造出的答案会和正确答案一样流畅。[幻觉](./幻觉（Hallucination）.md)本质上就是模型猜错了。

参数知识还会过时。参数在[知识截止日期](./知识截止日期（Knowledge%20cutoff）.md)之后就不再变化，因此在此之后发布或更名的库在参数里并不存在，而发生过变更的 API 也只会被记成旧形态。

对于这两种缺口——太冷门和太新——补救方法是一样的：知识无法写进参数里，只能改由上下文知识来提供。

_用法示例：_

“它写 React 代码完美无瑕，一写到我们内部 SDK 就开始捏造方法。”

“React 在参数知识里密度极高——有数百万条训练样本。你们的 SDK 没有，所以模型会自己脑补出看似合理的写法。把 SDK 文档加载进[上下文](./上下文（Context）.md)里吧。”
