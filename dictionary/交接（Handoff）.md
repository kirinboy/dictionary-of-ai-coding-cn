description: 将 Agent 上下文从一个会话传递到另一个会话，且没有回退路径。传递机制各异，包括交接产物、上下文压缩等。
---

将 [Agent](./Agent（智能体）.md) 的[上下文](./上下文（Context）.md)从一个[会话](./会话（Session）.md)传递到另一个会话。传递机制各不相同——书面[交接产物](./交接产物（Handoff%20artifact）.md)、内存中的摘要（[上下文压缩](./上下文压缩（Compaction）.md)）等。它与[清空会话](./清空会话（Clearing）.md)（完全不传递）不同。触发交接的原因多种多样：切换角色（规划者 → 实现者）、启动一次[无人值守（AFK）](./无人值守（AFK）.md)运行、扇出到多个并行会话，或腾出[上下文窗口](./上下文窗口（Context%20window）.md)空间。

接收方会话在启动时没有任何上下文——[模型](./模型（Model）.md)是[无状态](./无状态（Stateless）.md)的，旧会话中的任何内容对新会话都不可见。下一轮会话需要的一切都必须显式传递过去；其余内容都会消失。“没有回退路径”是决定传递内容的核心约束：新会话无法回过头去问旧会话当初是什么意思，因此传递过去的材料必须能够独立自足。

| 机制 | 形式 | 特性 |
| ---- | ---- | ---- |
| 交接产物 | [环境](./环境（Environment）.md)中的文件 | 你可以在任何后续工作依赖它之前阅读并修正；可在多个会话间复用 |
| 上下文压缩 | 上下文窗口中的摘要 | 自动且成本低；较难检查；仅供给单一后继会话 |

一次糟糕交接的典型表现是“重新争论”：新会话把旧会话早已敲定的决策推翻重来，因为传递的内容只记录了“决定了什么”，而没有记录“为什么这么决定”。评判交接质量的标准，就是看一个零上下文的新会话拿到它之后能做到什么程度。

_用法示例：_

“规划会话变得很臃肿了——我还要继续往下聊吗？”

“做一次交接吧。把决策写入文档，清空会话，然后开一个新会话读取这份文档来开始实现。”
