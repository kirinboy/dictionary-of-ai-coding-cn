开发者体验（Developer experience）——代码库及其工具链让人类开发者顺畅产出高质量工作的容易程度。良好的开发者体验（DX）意味着快速的反馈、清晰的报错信息、能回答你实际疑问的文档，以及第一次就能跑通的环境搭建。这个词早在 AI 编程出现之前就存在了；它被收录进本词典，主要是作为 [Agent体验（AX）](./Agent体验（AX）.md) 的对照。

DX 关注的是人类与代码库之间的交互——仅此而已。人类与 Agent 这两类受众最大的区别在于：人类是[有状态](./有状态（Stateful）.md)的，而 Agent 是[无状态](./无状态（Stateless）.md)的。人类只需学习一次代码库，就能把这份认知带到今后的每一天，这也是为什么糟糕的 DX 往往还能勉强凑合：人类会靠批量推送来绕过缓慢的 CI，靠在 Slack 里问一次同事来绕过缺失的文档，靠死记硬背文件位置来绕过混乱的目录结构。各种变通办法越攒越多，团队最终甚至能在一个处处与自己作对的代码库里保持高效。

[Agent](./Agent（智能体）.md) 面对的是同一个代码库，却没有任何历史积累。由于跨[会话](./会话（Session）.md)无状态，Agent 每次都必须从零开始重新认识代码库——它确实能从快速的测试套件和清晰的报错信息中受益，但它昨天摸索出来的一切经验都会清零，除非那些经验被写进了[环境](./环境（Environment）.md)里，而且 Agent 只能通过[工具返回结果](./工具返回结果（Tool%20result）.md)来感知它们。这正是 AX 所指代的鸿沟：当开发者变成 Agent 时，DX 中依然奏效的那部分，再加上人类根本不需要操心的问题——比如如何为[上下文窗口](./上下文窗口（Context%20window）.md)省出空间。

两者的交集意味着，改善 DX 的投入常常能顺带免费提升 AX——严格的类型、快速的测试以及可预测的结构对双方都有帮助。而两者的分歧意味着并非总是如此：一份图文并茂的新人入职文档能帮人类同事省心一周，但除非能从 [AGENTS.md](./AGENTS.md.md) 一路索引过去，否则对 Agent 毫无用处。

_用法示例：_

“我们的 DX 挺好的啊——新人一周就能上手干活了。”

“能上手是因为第一周有人坐在旁边带他们。Agent 可没有那一周的带教时间，还是单独检查一下 AX 吧。”
