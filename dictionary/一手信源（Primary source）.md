处于原始形态的真实信源——代码、完整对话记录、原始日志、真实的 API 响应。不是对事物的转述，而是事物本身。与[二手信源](./二手信源（Secondary%20source）.md)相对。

如果你想了解代码库实际在做什么，代码就是一手信源。文档、架构图和 README 都是对它的描述——在编写时或许准确，但此后便各自按照自己的节奏演进。当 [Agent](./Agent（智能体）.md) 自信满满地断言某个关于项目的错误事实时，应该追问它依据的是哪个信源：读文档的 Agent 会继承文档的过时问题；读代码的 Agent 看到的才是当下的真相。

成本是阻止一手信源成为默认选项的原因。把一手信源加载到[上下文窗口](./上下文窗口（Context%20window）.md)非常昂贵——完整的文件、完整的对话记录，每一个 [Token](./Token（词元）.md) 都会按[输入](./输入%20Token（Input%20tokens）.md)计费，并争夺[注意力预算](./注意力预算（Attention%20budget）.md)。付出这一成本换来的是完整性：没有任何内容被他人关于“什么更重要”的判断预先过滤掉。上个月写的摘要不可能包含今天才发现很关键的细节；一手信源里则依然保留着。

当精确度至关重要时——比如确切的函数签名、真实的报错信息、抛出异常的具体那一行——就去查阅一手信源。管理[上下文](./上下文（Context）.md)在很大程度上就是权衡何时值得为一手信源付费，以及何时二手信源就足够了。

_用法示例：_

“Agent 说重试逻辑采用了指数退避，但我明明看到它在疯狂请求接口。”

“它是从设计文档里读到的。让它去看实际的重试模块——当实际行为至关重要时，要以一手信源为准。”
