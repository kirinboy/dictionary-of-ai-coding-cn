[Agent](./Agent（智能体）.md) 所作用的世界——[Harness](./Harness（驾驭框架）.md) 之外的一切，Agent 通过[工具返回结果](./工具返回结果（Tool%20result）.md)感知它，并通过[工具调用](./工具调用（Tool%20call）.md)改变它。Harness 负责_运行_ Agent，而环境是 Agent _工作于其中_的场所。像 [`AGENTS.md`](./AGENTS.md.md) 这样的文件就存在于环境中，由 Harness 将其加载到[上下文窗口](./上下文窗口（Context%20window）.md)。[文件系统](./文件系统（Filesystem）.md)是最常见的环境形式，但并非唯一形式（数据库、远程 API、浏览器会话都可以成为环境）。

Agent 只有在主动查看时才能看到环境。它所知道的关于环境的一切，都是通过工具返回结果获得的，因此它对环境的认知是一系列快照的集合，每张快照仅在获取的那一刻准确。如果某个文件在 Agent 读取之后发生了变化——比如你手动编辑了它，或者构建步骤重新生成了它——Agent 会继续基于过时的副本进行推理，直到有某种因素促使它重新读取。Agent 自信地描述一个早已面目全非的文件，通常就是这个原因：环境变了，但快照没变。

环境也是唯一始终保持[有状态](./有状态（Stateful）.md)的持久化层。[会话](./会话（Session）.md)的上下文在会话结束后就会消失，但写入环境的文件会保留下来供下一次会话读取——这正是[记忆系统](./记忆系统（Memory%20system）.md)、[交接产物](./交接产物（Handoff%20artifact）.md)和 `AGENTS.md` 所依赖的机制。任何希望 Agent 明天依然知道的信息，最终都必须落盘到环境中。

环境的边界由你决定。[沙箱](./沙箱（Sandbox）.md)会缩小它，限制 Agent 能触及的范围；添加[工具](./工具（Tool）.md)则会扩展它，将数据库或 API 纳入可及范围。边界之内是 Agent 能感知和改变的一切；边界之外对 Agent 而言则不存在。环境对 Agent 工作的支持程度，就是该代码库的 [Agent体验（AX）](./Agent体验（AX）.md)。

_避免使用：_ 用“环境”指代运行时或 Harness 本身——Harness 是外层包装，环境才是工作空间。

_用法示例：_

“Agent 看不到预发布（staging）数据库的 Schema。”

“把它接入环境——给 Agent 配一个只读权限的预发布库 `psql` 工具。Harness 没问题，它只是没有可以作用的对象。”
