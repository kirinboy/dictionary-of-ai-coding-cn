[模型](./模型（Model）.md)真正做的事情。给定一段[上下文](./上下文（Context）.md)，它采样出下一个 [Token](./Token（词元）.md)，将其追加到末尾，然后再次运行。每一份输出——无论是一句话、一次[工具调用](./工具调用（Tool%20call）.md)，还是一个千行文件——都是这样一次一个 Token 地构建出来的。模型没有其他的运行模式。

每一步的运作方式完全相同：[上下文窗口](./上下文窗口（Context%20window）.md)里的 Token 经过[参数](./参数（Parameters）.md)计算，为词表中的每一个 Token 生成一个概率——这个 Token 接下来出现的可能性很高，那个则较低。接着根据这些概率采样出一个 Token，追加到末尾，然后带着变长了一点的上下文重新跑一遍循环。正是这个采样步骤，导致相同的提示词在不同运行中会产生不同的输出：[非确定性](./非确定性（Non-determinism）.md)是机制自带的属性，而不是叠加在上面的 Bug。

牢记这一机制，就能解释许多看似奇怪的行为。模型在输出一个 Token 之前，从不检查它是否_真实_——只关心它是否_像真的_（概率高）——这就是[幻觉](./幻觉（Hallucination）.md)的根源。它边生成边把每一个 Token 固定下来，因此一句听起来很自信的开场白，可能会把后面的整段回答都带偏。而且由于[输出 Token](./输出%20Token（Output%20tokens）.md) 严格地一次只生成一个，生成速度就决定了任何 [Agent](./Agent（智能体）.md) 工作速度的下限。

_用法示例：_

“Agent 是怎么‘决定’去调用一个工具的？”

“它并没有‘决定’——自始至终都只是下一个 Token 预测。工具调用本质上只是 [Harness](./Harness（驾驭框架）.md) 从输出流里解析出来的一段结构化字符串。”
