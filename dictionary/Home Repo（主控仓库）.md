一个存放你的 [Skill](./Skill（技能）.md)、[AGENTS.md](./AGENTS.md.md) 以及共享文档，并指向你其他代码仓库的仓库。你在 Home Repo 中运行 [Agent](./Agent（智能体）.md)，它会根据任务需要去打开或克隆其他仓库。

当一个项目横跨多个仓库时，在其中一个仓库里启动的 Agent 只能看到那一个仓库。结果每个仓库都有了自己的一份 Skill 和 Agent 配置拷贝，这些拷贝逐渐产生分歧，而且在跨仓库[追问式访谈（Grilling）](./追问式访谈（Grilling）.md)某个功能时也缺乏全局视角。Home Repo 只保留一份共享资料，且所有[会话](./会话（Session）.md)都从这里启动，而不是在单个业务仓库内部启动。

| 存放在 Home Repo 中                         | 留在各自仓库中                             |
| ------------------------------------------- | ------------------------------------------ |
| 跨仓库复用的 Skill                          | 该仓库的代码                               |
| AGENTS.md，包含指向各个仓库的指针           | 各自独立的 AGENTS.md、构建和测试命令       |
| 共享文档：编码规范、术语表、系统级决策      | 仅针对该仓库的文档                         |
| 工具链，例如将 Agent 连接到外部服务的 CLI   |                                            |

每个指针都是一个[上下文指针](./上下文指针（Context%20pointer）.md)：用一行写出仓库名称、磁盘位置，以及如果本地缺失时从哪里克隆。大约 20 个仓库时这种方式很好用。到了几百个仓库时，每个仓库一条指针会让 Agent 难以抉择，因此应改成每个业务领域对应一个文件，再把该领域的仓库列在里面（[渐进式披露](./渐进式披露（Progressive%20disclosure）.md)）。到了上千个仓库的规模时，Skill 的使用方已经足够多，改用 Skill 市场会更合适。

当你无法使用 Monorepo 时，Home Repo 可以作为替代方案：比如需要混用公开仓库和私有仓库，或者团队不愿采用 Monorepo。对团队而言，Home Repo 就是大家共享的那个工作底座。在[软件工厂](./软件工厂（Software%20factory）.md)中，Home Repo 会被放进[沙箱](./沙箱（Sandbox）.md)里，按需再去克隆其他仓库。

_避免使用：_ “agent repo”和“meta-repo”，这些是同一概念的旧称。

_用法示例：_

“我总是在往每个仓库里复制同一批 Skill，结果各个版本已经对不上了。”

“把它们挪到一个 Home Repo 里吧。只留一份 Skill，在 AGENTS.md 里指向各个仓库，以后都在那里启动会话。”
