只加载 [Agent](./Agent（智能体）.md) 当前所需的[上下文](./上下文（Context）.md)，其余部分通过[上下文指针](./上下文指针（Context%20pointer）.md)按需获取。这一概念借鉴自 UI 设计——在界面中只向用户展示与当前任务相关的控件，把其余选项收在点击操作后面。

这项技术之所以存在，是因为上下文会产生双重成本。预先加载的每一个 [Token](./Token（词元）.md)，在每一[轮次](./轮次（Turn）.md)都会作为[输入 Token](./输入%20Token（Input%20tokens）.md)计费，而且无论 Agent 是否用得上，都会消耗[注意力预算](./注意力预算（Attention%20budget）.md)。如果把完整的风格指南、部署手册和数据库约定一股脑塞进 [AGENTS.md](./AGENTS.md.md)，Agent 在这些方面都会表现得更差——真正对当前任务重要的指令，会被无关指令稀释。典型征兆就是 Agent 无视了你明明知道已在上下文里的规则：规则确实在里面，但被埋没了。

渐进式披露把这种方式反了过来。让常驻加载层保持精简——每个主题只写一句话，并附一个指向详情位置的指针。Agent 在编写组件时去读风格指南，在部署时去读部署手册，而在修复测试时这两份都不需要读。[Skill](./Skill（技能）.md) 就是内置在 [Harness](./Harness（驾驭框架）.md) 中的这种模式：每次[会话](./会话（Session）.md)只加载简短描述，完整指令仅在触发时才加载。

_用法示例：_

“我应该把整份风格指南都倒进 AGENTS.md 里吗？”

“别这样——用渐进式披露。把风格指南做成 Skill，让 Agent 真正需要写组件时再加载。AGENTS.md 里的内容每一轮都会消耗 Token。”
