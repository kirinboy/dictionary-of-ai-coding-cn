description: 当对话保真度不够高、需要真实产物来讨论时，让 Agent 快速构建一个粗糙版本。
---

让 [Agent](./Agent（智能体）.md) 快速构建某个东西的粗糙版本，用于对话保真度不够高、你需要一个真实产物来展开讨论的场景。

[追问式访谈（Grilling）](./追问式访谈（Grilling）.md)是在对话中敲定设计决策。对话成本很低，但保真度也低：有些问题无法靠语言文字回答——比如交互手感如何、某个 API 形态在实际调用代码里用起来顺不顺手、页面布局在真实数据量下撑不撑得住。访谈问到这类问题时，你最诚实的回答只能是“我不知道，我得看到实物才能定”。过了这个节点，光靠讨论只会在原地打转。这时候不如让 Agent 直接把东西做出来，看一眼，再带着明确答案回到对话中。

Agent 大幅降低了构建成本，这才让原型构建变得切实可行。过去需要花一天才能搭出来的粗糙版本，现在几分钟就能搞定，因此值得把它变成常规动作。这也是一种[人在回路（HITL）](./人在回路（Human-in-the-loop）.md)的技巧：原型存在的意义，就是让你对着它给出反应。

通常你不会只看一眼就结束。对着原型不断迭代——给出反应、要求修改、再给出反应——每一轮都在用比纯对话更高的保真度，对着真实产物敲定一个又一个决策。

原型并不一定非得全都是凑合的草稿。你可以把正在重点评估的那部分直接按生产级质量来构建，这样一旦决策落定，你测试并认可的组件或 API 就能直接迁移进真实的代码库。这也使原型成为 [Spec](./Spec（规格说明书）.md) 引用时不可或缺的参考材料。

_用法示例：_

“关于这个向导流程到底做成一个页面还是分三步，我们已经争了半小时了。”

“光嘴上说定不下来——让 Agent 把两个原型都做出来。我们点一遍，五分钟就有答案了。”
