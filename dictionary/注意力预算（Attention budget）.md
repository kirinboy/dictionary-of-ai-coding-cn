每个 [Token](./Token（词元）.md) 能够分配给[上下文](./上下文（Context）.md)其余部分的影响力总量是有限的。在[某一段关联](./注意力关联（Attention%20relationship）.md)上倾注了大量影响力，留给其他关联的就少了。这个预算是按单个 Token 固定的，不会随着上下文变长而增长，这正是长[会话](./会话（Session）.md)会稀释注意力的原因。

可以把它想象成信号与噪音。你的指令是一段音量固定的信号；[上下文窗口](./上下文窗口（Context%20window）.md)里的其他每一个 Token 都是与之竞争的声响。指令本身从未变小声——它一字不差地待在那里——但随着上下文增长，四周的房间变得越来越嘈杂，信噪比随之下降。在 10k Token 上下文中原本最响亮的指令，到了 150k 时就成了背景嗡嗡声。这就是[注意力退化](./注意力退化（Attention%20degradation）.md)背后的机制：模型并没有遗忘，而是信号被淹没在了噪音里。

这种症状表面上看像是不听指令——Agent 早期明明答应遵守某个约束，后来却逐渐偏离，重新粘贴一遍约束也只能管用一会儿。问题不在于指令本身，而在于窗口里的其他所有内容都在和它争夺注意力。

你能控制的是放进上下文里的内容。不服务于当前任务的内容并不是中立无害的——它会成为压制所有有效信息的噪音。保持窗口精简，在累积的上下文不再物有所值时及时[清空会话](./清空会话（Clearing）.md)，并重申关键约束，而不是指望早前提过一次就能一直生效。

_用法示例：_

“为什么它老是无视我贴在最前面的 schema？”

“我们已经深入[愚钝区](./聪明区（Smart%20zone）.md)了——每个 Token 的注意力预算是固定的，但上下文却在不断膨胀。schema 上的信号现在正和成千上万个新进来的 Token 竞争。”
