一条用户消息以及 [Agent](./Agent（智能体）.md) 为此执行的所有响应动作，直到它将控制权交还给用户为止。其中包含一次或多次[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)——如果 Agent 调用了[工具](./工具（Tool）.md)，通常会有多次。Agent 提出澄清问题会结束当前轮次；你的回复则会开启下一个轮次。层级关系为：[会话](./会话（Session）.md) **> 轮次 > 模型提供商请求**。

之所以值得单独命名“轮次”，是因为它的长度由 Agent 决定，而不是由你决定。你只发出了一条消息；Agent 自己决定在交还控制权之前要串联多少次工具调用。一个轮次可以是一句简短的回答，也可以是长达二十分钟的读文件、改代码和跑测试。这是同一特性的正反两面：长轮次让[无人值守（AFK）](./无人值守（AFK）.md)成为可能，但长轮次也是无监督情况下容易跑偏的地方——等 Agent 终于停下来交还控制权时，它可能已经偏离你的本意很远了。

轮次也是最自然的纠偏单位。轮次内部发生的一切都没有你的参与；轮次之间的间隙才是你重新调整方向的时候。大多数 [Harness](./Harness（驾驭框架）.md) 对此做了柔化处理：你可以在轮次中途打断 Agent 来叫停并纠正它，或者在它干活时先输入一条消息，等当前轮次一结束就让它读到。如果你发现自己总是对轮次结束时的结果不满意，解决办法通常是要求更小的轮次——先出计划，再一步一步执行——用一部分自主性换取更频繁的纠偏机会。

_用法示例：_

“一个轮次居然跑了两分钟？”

“它在这个轮次里做了十四次[工具调用](./工具调用（Tool%20call）.md)——每一次都是单独的模型提供商请求。在 Agent 最终把控制权交还给你之前，延迟就这样一步步叠加起来了。”
