[Agent 模式](./Agent%20模式（Agent%20mode）.md)中负责权限门控的部分——决定哪些[工具调用](./工具调用（Tool%20call）.md)会触发[权限请求](./权限请求（Permission%20request）.md)，哪些会自动执行。在各类 [Harness](./Harness（驾驭框架）.md) 开始把行为指令捆绑进模式系统之前，这正是模式系统原本的用途。

Harness 通常提供一套阶梯式的权限模式：

| 模式                 | 读取 | 写入与 Shell               | 典型用途                                              |
| -------------------- | ---- | -------------------------- | ----------------------------------------------------- |
| 只读 / 规划（Plan）  | 自动 | 阻止                       | 调研、规划、审查                                      |
| 默认（Default）      | 自动 | 询问                       | 日常受监督的工作                                      |
| 自动编辑（Auto-edit）| 自动 | 编辑自动执行，Shell 询问   | 受信任的仓库、机械性修改                              |
| “Yolo” / 全自动      | 自动 | 自动                       | [沙箱](./沙箱（Sandbox）.md)环境、[无人值守（AFK）](./无人值守（AFK）.md)运行 |

选择哪一档是在安全性与打断频率之间做权衡，而两端失衡的痛点都很明显。设得太紧，你就会成为瓶颈：[Agent](./Agent（智能体）.md) 每隔几秒就因为无害的读取操作停下来一次，你开始条件反射地一路点批准，审批也就失去了意义——走过场式的批准是最糟糕的结果，既承受了所有打断，又没获得任何保护。设得太松，Agent 就会在你还没来得及看一眼之前直接修改文件、运行命令。

最宽松的那一档，只有在[沙箱](./沙箱（Sandbox）.md)内部才最站得住脚，因为那里把一次糟糕[工具](./工具（Tool）.md)调用的爆炸半径限制住了。在沙箱之外，大多数人都会选择自动批准读取操作，而把[人在回路（HITL）](./人在回路（Human-in-the-loop）.md)的把关留给任何不可逆的操作。

_用法示例：_

“它每次 grep 都要停下来问我——把我的无人值守运行彻底搞砸了。”

“把只读工具的权限模式放宽，写入和 Shell 保持提示即可。在调研型[会话](./会话（Session）.md)里，大多数权限请求都只是噪音。”
