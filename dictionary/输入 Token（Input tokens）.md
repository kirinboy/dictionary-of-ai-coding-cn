[Harness](./Harness（驾驭框架）.md) 在每次[模型提供商请求](./模型提供商请求（Model%20provider%20request）.md)中发送给模型的 [Token](./Token（词元）.md)——包括 [System prompt](./System%20prompt（系统提示词）.md)、对话历史、[工具返回结果](./工具返回结果（Tool%20result）.md)，即[模型](./模型（Model）.md)在开始生成前读取的一切内容。由于处理开销低于[输出 Token](./输出%20Token（Output%20tokens）.md)，其计费单价也更低。

在进行 [AI](./AI（人工智能）.md) 编程时，输入 Token 占了你账单的大头。模型是[无状态](./无状态（Stateless）.md)的，因此每个[轮次](./轮次（Turn）.md)都会把整个[会话](./会话（Session）.md)作为输入重新发送一遍：你的第一条消息、之后的每一次回复、以及此后所有的工具返回结果。第 50 个轮次的输入里包含了前 49 个轮次的全部内容。单次模型提供商请求可能只生成几百个输出 Token，却要重新发送多达十万个积累下来的历史输入 Token。

[前缀缓存](./前缀缓存（Prefix%20cache）.md)能降低这笔开销：与先前请求完全匹配的历史前缀会按低价的[缓存 Token](./缓存%20Token（Cache%20tokens）.md) 计费，而不是按全价输入计费。当输入成本依然过高时，解决办法就是缩减每次重发的内容——在任务之间执行[清空会话](./清空会话（Clearing）.md)或[上下文压缩](./上下文压缩（Compaction）.md)。

_用法示例：_

“账单这么高，可 [Agent](./Agent（智能体）.md) 几乎没写什么代码啊。”

“全花在输入 Token 上了——每个轮次都会把整个会话重发一遍。要是没有前缀缓存，每次请求你都得为历史记录重新付一遍钱。”
